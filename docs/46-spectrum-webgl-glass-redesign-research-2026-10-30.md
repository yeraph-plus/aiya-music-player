# docs/46 — 频谱视觉升级调研：three.js 画笔、真毛玻璃、正在播放页重做

日期：2026-10-30。背景：用户提出五项改动——背景加动态渐变、山形频谱换画笔加光晕、
高斯模糊换真毛玻璃、正在播放页整体重做（盖住侧栏 / 重排版 / 避开歌词）、
两页频谱设置拆成独立开关。

本文只做**调研与计划**，不动代码。所有性能数字来自本机实测（脚本见 §10）。

## §0 结论先行

| # | 方向 | 结论 | 关键依据 |
|---|---|---|---|
| 1 | 背景慢速流动渐变 | **做**，但要挂在同一 WebGL 上下文里，且 CSS 渐变仍是底色真源 | 单个全屏 pass 成本 < 0.1ms；色板迁移风险靠"叠加层"规避 |
| 2 | 山形换画笔 + 边缘光晕 | **做**，但必须先解决"平滑"（heightfield 线性插值会出折角） | 实测：WebGL 版比现状**更便宜**（现状每帧 `filter: blur(14px)` 才是大头） |
| 3 | 真毛玻璃 | **能做，且性能顾虑不成立**——推翻 docs/25 §5 的"红线" | 全屏玻璃覆盖层 DPR2 吞吐 −14%，绝对单帧 0.3ms；静态底色时成本为 0；5K 渲染下与不开玻璃的掉帧数落在同一噪声区间（§2.2d） |
| 4 | 正在播放页盖侧栏 + 重排版 | **做**，但不用覆盖层：**侧栏在正在播放页整体退出**，主区跨满两列，全应用只留唯一一套背景 | 覆盖层要自己画底/加玻璃，等于为一个页面再叠一层合成；侧栏退出后背景层天然连续，且省掉最贵的那块全屏玻璃 |
| 5 | 两页频谱独立开关 | **做**，`spectrum` 拆成 `bgSpectrum` / `npSpectrum` | `RemoteSpectrumSource` 已是引用计数，零改动即可支持两个消费方 |

一个必须先讲清的取舍：**"边缘光晕"与"现在这种柔雾"在视觉上是矛盾的**。现状是
48 带 → 160×90 buffer → `blur(14px)` → 放大，山脊几乎不可辨，只剩一团会呼吸的光
（截图 `tools/bench/shots/canvas.png`）。加了光晕，脊线就会变清晰、有轮廓
（`tools/bench/shots/webgl.png`）。这不是纯增益，是**观感定调的变化**，需要拍板
（见 §3.2 的三个档位）。

## §1 现状盘点

### 1.1 数据流（不变的部分）

```
Rust 引擎 PCM → FFT → 48 对数分带 u8[48]
   → spectrum:frame（30fps 事件）
   → RemoteSpectrumSource.frame()   // 归一化 0–1，同一个 Float32Array 就地覆盖
   → 两个消费方各自的 rAF 循环取帧绘制
```

`start()/stop()` 是**引用计数**的（docs/26 补遗）：tap 是全局开关，多消费方共享一个
实例。所以 §5 的"拆两个开关"不需要动数据层——两个组件各自
`if (开关) source = player.getSpectrumSource()`，引用计数天然处理"只开一个"与"都关"。

### 1.2 两套渲染

| | 背景环境光 | 正在播放页 |
|---|---|---|
| 文件 | `components/AmbientBackdrop.svelte` | `components/NowPlayingSpectrum.svelte` |
| 引擎 | Canvas 2D | Canvas 2D |
| 形态 | 远山 + 近山，中点二次贝塞尔，填充渐变 | `mirror` / `radial` / `wave` 三形态 |
| 光 | `ctx.filter='blur(14px)'` + 低分辨率 buffer 放大 | `shadowBlur` 描边 |
| 覆盖 | 全窗口（`inset: 0`，第 2 层） | 正在播放页 `inset: 0`（z-0，压在内容后） |

背景层性能模型的原始论证在 docs/26 §1：模糊代价 ∝ 像素数，所以画在 160×90 上。
**这个论证今天依然成立**，但它只覆盖了"模糊"这一项，没覆盖 `ctx.filter` 在软件光栅
下的真实代价（§2.3 有反例）。

### 1.3 已存在的设计红线（本次要动它）

`Sidebar.svelte` / `TitleBar.svelte` / `player.css` 三处都写着同一句话：

> 不用 backdrop-filter——它是持久壳层，垫着动画频谱 canvas 就是每帧全条重模糊
> （docs/25 §5 方案 B 红线）。

这条判断在当时是**推理**（没有实测），§4 用数据逐条核对它是否还成立。

### 1.4 three.js 现状

`ui/package.json` 有 `three ^0.186.1` + `@types/three`，但**全仓 `ui/src` 零引用**
（`grep -rn "three" ui/src` 为空）。也就是说画笔已经买回来了，还没握。

实测体积（`rolldown` tree-shake + minify，只 import 渲染必需的 8 个符号）：

```
three tree-shaken min 513KB  gzip 126KB
```

tree-shaking 几乎无效（全量 647KB / 128KB gzip）——`WebGLRenderer` 把材质、纹理、
着色器库全拖进来了。这是本地应用（资源走磁盘），126KB 的传输成本可忽略，但**它意味着
"用 three"不是一个可以只付一点点的选择**：要么用，要么不用。

## §2 实测：性能基准

### 2.1 方法

`tools/bench/spectrum-bench.html` 复刻三种背景管线，`tools/bench/collect.mjs` 用
**系统 Edge（与 WebView2 同引擎）的 headed 窗口**采集。headless 走 SwiftShader 软件
光栅，数据没有参考价值，所以必须 headed。

场景：

| 场景 | 内容 |
|---|---|
| `canvas` | 现状管线复刻：160×90 buffer + 中点贝塞尔双山 + `blur(14px)` 放大 |
| `webgl` | three 全屏 shader：48 带走 48×1 浮点纹理 → 逐像素距离场出填充/描边/三层光晕 + fbm 流动底色 |
| `*-glass` | 侧栏（240×712，真实应用 `--sidebar-w: 216`，面积同量级）+ 播放条（全宽×88）两块 `backdrop-filter: blur(24~28px) saturate(180%)` |
| `*-overlay` | 整页覆盖层 `blur(30px) saturate(170%)`（"盖住侧栏"的形态） |

仪器：rAF 间隔（p50/p95/p99/掉帧数）+ `PerformanceObserver` 长任务。
用 `--disable-gpu-vsync --disable-frame-rate-limit` 解除 60Hz 上限，否则所有场景都贴在
60fps，差异全被 vsync 掩盖（第一轮就是这样，白测）。

**硬件**：`ANGLE (Intel, Intel(R) Arc(TM) Graphics, D3D11)` + Windows。

### 2.2 结果

**（a）vsync 开启时——找不到差异**

1280×800 @1x/2x、2560×1440 @2x（即 5120×2880 渲染）：6 个场景**全部** 60fps，
p95 ≤ 16.8ms，零长任务。在这台机器上，这三项改动**都不是性能问题**。

**（b）解除 vsync（1920×1080）——CPU 侧吞吐**

| 场景 | DPR1 | DPR2 | 相对 `canvas` |
|---|---|---|---|
| `canvas`（现状） | 4056 fps | 3673–4105 fps | — |
| `canvas` + 侧栏/播放条玻璃 | 3748 | 3409 | ≈ −16% |
| `canvas` + 全屏玻璃覆盖层 | 3865 | 3310–3630 | ≈ −14% |
| `webgl`（fbm + 双山 + 三层光晕） | 2814 | 2248–2854 | ≈ −35% |
| `webgl` + 玻璃 | 3287 | 2973 | 噪声内 |
| `webgl` + 全屏覆盖层 | 2416 | 1906 | ≈ −40% |

换算成单帧：最贵的一档 0.2–0.5ms，相对 16.7ms 的预算 **< 4%**。
（多次跑同一场景有 ±10% 波动，这张表取的是复测区间，不是单次最优值。）

**（d）卡顿归因复核（2026-10-30 追加）**

用户看 §2.2(b) 的原始输出时提到"大分辨率下明显卡顿"，指向的是解除 vsync 组里
`max: 926ms`、`over50: 15` 这类数字。复核结论：**那不是玻璃，也不是真实使用场景。**

| 2560×1440 @DPR2（= 5120×2880 渲染），vsync 开启 | 掉帧 >25ms | max |
|---|---|---|
| 无玻璃（`canvas`） | 3 / 2 / 0 | 25.4 / 25.2 / 18.9 ms |
| 侧栏+播放条玻璃（`canvas-glass`） | 0 / 2 / 0 | 20.4 / 33.2 / 17.1 ms |

三轮交错，玻璃组**不比无玻璃组差**，p95 都是 16.8ms——掉帧是测量噪声（GC / 系统调度 /
Playwright 截帧）。900ms 尖峰只出现在 `--disable-gpu-vsync` 组：那组为了比吞吐把帧跑到
2000–4000fps，CPU 队列饱和后必然出现长尾，不代表 60Hz 下的表现。

真正的约束是**面积 × DPR²**：玻璃面板越多、屏越大，边际成本越接近预算。这也是
"全局 3D 开关 + 能力探测降级"必须存在的理由（§6.2 / §7）。

**（c）软件光栅（SwiftShader，模拟远程桌面 / 无 GPU 加速 / 老核显关硬件加速）**

| 场景 | 结果 |
|---|---|
| `canvas`（现状管线） | **卡死，120s 内跑不完一次测量** |
| `webgl`（shader） | p50 0.2ms / p95 1.3ms / p99 2.8ms（0.5x 分辨率） |

这一格是本次调研最意外的发现：**现状的 `ctx.filter='blur(14px)'` 在软件光栅下比
WebGL shader 还慢**，慢到跑不完。所以"上 WebGL 会给低端机带来新风险"这个直觉是反的——
风险一直在，只是从没在无 GPU 的机器上验过。

（注：这不是说 WebGL 在软件光栅下就能用，60fps 仍然不用想。结论只是：**两边的降级
策略都得有，而不是"为了安全继续留在 Canvas 2D"**。）

### 2.3 从数据里能得出的三条

1. **性能不构成这三项改动的决策变量**。真正的变量是观感、维护成本、一致性。
2. **玻璃的成本与"背景是否在动"强绑定**：静态底色下 `off-glass` 与 `off` 完全一致
   （Chromium 会缓存 backdrop 的模糊结果）。这直接给了 §5 一个漂亮的性质——
   关掉背景动态频谱 ⇒ 玻璃退化成一次性模糊 ⇒ 持续成本归零。
3. **成本排序**：全屏玻璃 ≈ 侧栏+播放条玻璃 < WebGL shader 层。都不该成为阻碍。

## §3 方向一 & 二：three.js 重绘背景层

### 3.1 结构：底色不动，只叠"光"

不要用 shader 重画那 5 套渐变。理由：

- 5 套方案 × 深浅两主题 = 10 组色值在 `tokens.css`，是**设计资产的唯一出处**。
  搬进 shader 等于把调色权从 CSS 挪到 TS，改一次要动两处，而且 `--ambient-bg` 还
  被别处读（首帧兜底、`data-ambient` 切换）。
- CSS 渐变是**静态**的，成本为 0；它是"确定的视觉身份"（docs/25 T4d 的拍板）。

所以分层是：

```
第 1 层  .ambient-art      CSS var(--ambient-bg)         静态，真源
第 2 层  <canvas> flow     additive 低频光斑（慢速流动）    新增，可由设置关闭
第 3 层  <canvas> ridge    山形频谱                      换 WebGL（保留原算法）
第 4 层  界面布局                                        不动
```

两层 canvas 合成一个（同一 renderer 画两遍），见 §7。

流动渐变的实现要点：3 octave fbm + 域扭曲（domain warp），时间系数 0.06
（一分钟量级走完一个周期——"慢"是需求，不是参数）。颜色由 `--accent` 与方案色传入
uniform，切方案只换 uniform，不重建上下文。这一层做不到 CSS 的"固定渐变"，但能做
CSS 做不到的**有机流动**（烟在流，而不是两团光在平移）。

### 3.2 山形：算法保留，只换光栅器

用户对当前山形"很满意"，所以**脊线的数学一行不改**：

- 48 带时间平滑 0.3/帧（起音跟手、衰减绵长）
- `v^1.2` 伽马压低持续偏热的低频
- 远山 = 倒序带 + 0.5 振幅 + alpha 0.35；近山 = 主形 + 0.82 振幅 + alpha 0.7
- 纵向渐变：峰顶浓、底边透明

要换的只有"怎么把这条脊线变成像素"：

| | 现状 Canvas 2D | WebGL |
|---|---|---|
| 曲线 | 中点二次贝塞尔 | 先把 48 带 **重采样到 256 点**（Catmull-Rom），再传 256×1 浮点纹理 |
| 填充 | `linearGradient` + `fill` | fragment 里 `smoothstep` 山体 |
| 描边 | 无 | `exp(-|d|·110)` |
| 光晕 | 无（整层 blur） | `exp(-|d|·22)` + `exp(-|d|·6)` 两层指数衰减 |
| 柔化 | `ctx.filter='blur(14px)'` | 渲染到 0.5x 再上采样（等效，但便宜）+ halo 项自带弥散 |

**必须先解决的坑**：shader 里若直接用 48 点线性插值，会出现明显折角
（`tools/bench/shots/webgl.png` 里能清楚看到锯齿状山脊）。现状之所以圆润，是因为
CPU 端做了中点二次贝塞尔。所以重采样不是优化项，是**正确性前置条件**。

**几个光晕档位**（同一 shader，只改系数，可以做成设置项）：

| 档 | rim | glow | halo | 观感 |
|---|---|---|---|---|
| 柔雾（接近现状） | 0.15 | 0.20 | 0.28 | 脊线若有若无，纯氛围 |
| 平衡（建议默认） | 0.42 | 0.26 | 0.12 | 脊线可辨、边缘有光，仍是一团光（`shots/webgl.png`） |
| 锐光（"霓虹"） | 0.75 | 0.35 | 0.06 | 清晰的山脊 + 紧贴边缘的强光 |

建议默认"平衡"，并把档位并进 §5 的设置（`ridgeGlow`），让用户自己定调——
这比一次性拍板安全，因为这是审美判断。

### 3.3 为什么不是"继续用 Canvas 2D 加光晕"

Canvas 2D 的 `shadowBlur` 是**逐图元**重算：每个 `stroke()` 都要在包围盒内做一次高斯，
半径大时 Chromium 会退回软件路径；而且它只能在描边周围加光，做不出"离脊线越远越淡、
衰减曲线可调"的连续光带。WebGL 的逐像素指数衰减天然连续，**成本与半径无关**
（多算一个 `exp`），且填充/描边/光晕一次出完，无离屏、无 blur pass。

## §4 方向三：真毛玻璃

### 4.1 先纠正一个概念混用

现在的 `blur(14px)` **不是毛玻璃**，是"背景光斑自身的柔化"。两者作用对象相反：

- 现在：把**背景内容**画糊（低分辨率 buffer + filter），糊完再交给合成器放大；
- 真毛玻璃：`backdrop-filter` 作用在**前景的面上**（侧栏 / 播放条 / 覆盖层），
  把"它身后的一切"采样、模糊、提亮饱和后再合成。背景内容本身不变。

所以"把高斯模糊改成真毛玻璃"不是替换，是**新增一层**：背景光斑该糊还得糊
（那是氛围），玻璃是给面加质感。两者可以同时存在，也可以独立开关。

### 4.2 docs/25 的红线还成立吗

不成立。红线的前提是"每帧全条重模糊 = 太贵"，实测：

- 侧栏 + 播放条两块玻璃：吞吐 −16%，绝对 0.2ms；
- 全屏覆盖层（面积最大的形态）：DPR2 下 −14%（复测 3310/3630 vs 基线 3993/4105）；
- 静态底色时：**零额外成本**（`off-glass` 与 `off` 完全一致，blur 结果被缓存）。

当时的判断缺一个量级估计。现在有了：**玻璃的成本约等于"多画半帧背景"，不是"多画十帧"**。

### 4.3 但红线的直觉有真实内核——要留住它的边界

能让玻璃真的变贵的情况，必须写进实现约束：

1. **嵌套 backdrop-filter**：内层采样的是外层合成后的结果，Chromium 会退化成两次
   全屏模糊。**禁止在玻璃面板内部再放玻璃元素**（菜单/气泡用不透明 `surface-4`）。
2. **`filter` / `transform` / `opacity` 祖先**：会让 backdrop 根变化，最坏情况是
   "玻璃失效"或"每帧重建 backdrop 纹理"。玻璃元素的祖先链要干净。
3. **大面积 + 4K + 低端核显**：DPR2 下面积 ×4，§2.2 的 −14% 会放大成 −40% 量级。
   需要 §7 的 GPU 探测：软件光栅 / `Basic Render Driver` → 玻璃降级为不透明底色。
4. **半径不是越大越好**：24–30px 之后观感收益急剧衰减，成本仍线性涨。默认 28px。

### 4.4 苹果式配方的拆解

真正像 Apple 毛玻璃的不是 `blur()` 一个属性，是四件套：

```
background:      color-mix(in srgb, var(--surface-2) 55%, transparent)
backdrop-filter: blur(28px) saturate(180%) brightness(1.06)
border:          1px solid rgba(255,255,255,.09)        ← 边缘"厚度"
box-shadow:      inset 0 1px 0 rgba(255,255,255,.12)    ← 顶部高光
+ 噪点 overlay：SVG feTurbulence 生成的 3% 灰噪（一次性贴图，不重绘）
```

后两项是纯 CSS/静态图，零持续成本，但贡献了大半"玻璃感"。**只加 blur 会觉得"糊"，加了
边缘高光和噪点才像"玻璃"**——上面 `shots/webgl-glass.png` 里左侧栏只做了 blur +
半透明底，已经能看出"更亮更雾"，但仍然偏"塑料"。

噪点必须用**静态贴图 + `background-image` 平铺**，不能用 CSS 动画或 SVG filter 实时生成
——那会强制每帧重绘，把"零成本"变成"最贵"。

## §5 方向四：正在播放页重做

### 5.1 先核实问题描述

用户说"封面定位和歌词使用固定定位"，代码里其实没有 `position: fixed`。真实问题是
**硬编码的几何假设**（`styles/pages.css`）：

```css
.now-playing-page { grid-template-columns: minmax(260px,4fr) minmax(0,6fr); gap: 44px; }
.np-cover  { width: min(240px, 100%); }                    /* 永远 240，大屏不涨 */
.np-info   { display:flex; justify-content:center; }        /* 封面"上下居中" */
.np-meta   { position:absolute; top: calc(50% + 120px + 18px); }  /* = 半封面 120 + 呼吸 18 */
```

三处失效场景：

1. **大屏**：2560 宽时左列 4fr ≈ 960px，封面还是 240px → 封面缩成一个小方块浮在
   巨大空白里；`.np-meta` 还钉在"中线 +138px"，与封面的相对关系靠巧合维持。
2. **矮窗**（600 高，`minHeight` 就是 600）：封面 240 已占 40% 高，`.np-meta` 从
   50%+138 = 438px 开始往下排，很容易顶出底部或被播放条压住。
3. **歌词行宽**：右列 60% 宽，2560 下每行 1400px——中文歌词一行能塞 70 字，
   阅读时视线要横跨半米。这是"大屏效果不好"最实际的来源。

### 5.2 盖住侧栏：让侧栏退出，而不是盖一层（用户 2026-10-30 拍板）

我原方案是"覆盖层 + 自己画底/玻璃"，用户否掉了，理由更对：**那等于为了一个页面再叠
一层合成，而背景本来就该只有一层。**

| 方案 | 做法 | 评价 |
|---|---|---|
| A 覆盖层（原方案，否） | `.app` 内绝对定位层 + 自己的底/玻璃 | 背景被"复制"了一层；最贵的全屏玻璃正是它 |
| **B 侧栏退出（采用）** | 正在播放页时 `.app` 第一列塌到 0、侧栏 `visibility:hidden`，主区自然铺满 | 背景层全应用唯一，且**尺寸不变**（见下） |
| C 路由级重挂载 | 整页替换 AppShell 内容 | 播放条/背景要跟着重建，最贵 |

B 的三条好处，按重要性排：

1. **背景只有一套**。`AmbientBackdrop` 本来就是全窗口 `inset:0`（docs/25 T4c 的 app 化），
   它从没被"挡住"——挡住它的是侧栏那块 82% 不透明的面板。侧栏一退，背景连续地铺满
   整个窗口，正在播放页**零额外背景绘制**。
2. **省掉最贵的那块玻璃**。§2.2 里 `*-overlay` 是成本最高的一档（全屏 `blur(30px)`）；
   B 方案下正在播放页没有任何新玻璃，只有既有的侧栏/播放条那两块——而侧栏此时已经退出，
   只剩播放条。
3. **背景 canvas 的尺寸不抖动**。这是容易忽略的一点：背景层是 `inset:0` 的全窗口层，
   侧栏进退不改变它的 `clientWidth/clientHeight`，所以 `AmbientBackdrop` 的 resize 逻辑
   不会重建 buffer、山形不会跳一帧。覆盖层方案反而要多考虑"覆盖层尺寸与背景层尺寸
   不一致"。

实现（`AppShell` 拿 `ui.page === 'nowPlaying'` 派生一个状态写到 `.app` 上）：

```css
.app { transition: grid-template-columns 180ms ease; }
.app[data-np='true'] { grid-template-columns: 0 1fr; }
.app[data-np='true'] .sidebar {
  /* 列宽塌到 0 后内容仍会溢出绘制，必须同时收掉可见性与溢出 */
  visibility: hidden;
  overflow: hidden;
  pointer-events: none;
  opacity: 0;
}
```

要点：

- **不能只写 `display:none`**：那会打断 180ms 的列宽过渡（display 不可动画），侧栏会
  "啪"一下消失。`visibility` 是离散属性，可延迟切换，正好配合列宽过渡。
- `grid-template-columns: 0 1fr`（不是 `0px`）在现代 Chromium 里可插值，过渡顺滑。
- **TitleBar 不动**：`.tb-brand` 定宽 216 与侧栏对齐，但窗口按钮（最小化/关闭）在右上，
  顶栏必须留。品牌区继续占 216 不影响观感（它是"应用标题"，不是导航）。
- 侧栏退出后**导航入口消失**，退路只有三条，且都走同一条历史栈：顶栏「返回上一页」、
  播放条歌曲区（开关）、`Esc`。**页内不放返回键**（2026-10-30 用户拍板）：顶栏已经
  自带一级返回，页内再放一个圆形按钮就是同一条动作的第四个入口，纯冗余。
- 播放条歌曲区从"入口"升级成**开关**：`aria-expanded` 同步、`Esc` 与顶栏返回走同一条栈。
  "这里还有一页"的提示改过一版：先是封面右下角压一个 16px 折线箭头角标，**当天被撤**
  —— 静止时也在，等于从 48px 的封面裁掉一个角、又小到看不清。现在是盖满封面的
  hover 提示（`rgba(0,0,0,.5)` 蒙版 + 20px 折线箭头，`pointer-events:none`），
  只在 `:hover` / `:focus-visible` 淡入，朝上 = 可展开、朝下 = 已展开。
  `svg` 由 ChevronUp 组件渲染，Svelte 选不到 `.now-cue svg`（check 会报未使用选择器），
  所以外面多包一层 `.now-cue-icon` 当动画载体。
  注意冷启动陷阱：路由状态持久化、返回栈不持久化，落在这一页时栈是空的，
  `back()` 无操作 —— 退出必须走 `nav.exitNowPlaying()`（栈空落到首页），
  否则侧栏已退出的这一页会成为**死路**（实测复现过）。

### 5.2b 一个必须承认的取舍

侧栏退出意味着**正在播放页没有侧栏导航**（Apple Music / Spotify 也是这样）。如果之后
发现用户想"边看歌词边切歌单"，替代方案是把侧栏做成浮动抽屉（`SideDrawer` 已有零件），
而不是回到常驻侧栏——常驻就意味着背景又断一次。

### 5.3 新布局

```
┌──────────────────────────────────────────────────────────┐
│ titlebar（保留）                                          │
├──────────────────────────────────────────────────────────┤
│  ← 返回                                                   │
│  ┌─────────────┐                                          │
│  │             │   歌名 / 专辑 / 艺人                      │
│  │   封面       │   格式徽章                                │
│  │  clamp()    │   ─────────────────────────              │
│  └─────────────┘   [频谱：窄带，只在信息区右侧]              │
│                                                          │

│                     ▲ 高亮行                              │
├──────────────────────────────────────────────────────────┤
│ player dock（保留）                                       │
└──────────────────────────────────────────────────────────┘
```

关键改动：

1. **封面不再固定 240px**：`width: clamp(180px, 24vh, 320px)`——按**高度**走而不是按
   宽度，因为封面的视觉权重应该跟窗口高度挂钩（横屏大屏不该让封面变小）。
2. **信息块回到流内**：`.np-meta` 从 `position:absolute` 改回 flex column 的第二项，
   用 `gap` 控制间距。这样封面尺寸一变，信息自动跟随——去掉"半封面高 + 18px"这个
   一次性算术。
3. **页面内容整体限宽居中**：`max-width: min(1180px, 92%)`，两列改
   `minmax(260px, 340px) minmax(0, 1fr)`。大屏上多出来的宽度变成两侧留白，而不是
   变长的歌词行。
4. **歌词限宽**：`.lyrics-lines { max-width: 26em; }`（中文 ≈22–26 字），
   行高 1.7。竖屏窄窗时自然收缩。
5. **垂直**：从"封面精确居中"改成"内容块整体在可用高度内居中，但歌词区独立滚动"。
   现有"上下各半屏占位"（`.lyrics-pad`）的逻辑保留——那是把首尾句也能滚到中线，
   与封面居中无关。

### 5.4 频谱与歌词重叠

这是 §5 里最需要设计判断的一条。现状：`np-spectrum` 是 `inset:0`，镜像曲线的中线
= 页面中线 = **歌词激活行所在的水平线**（激活行被滚到容器中线）。曲线正好横穿
最需要读的那一行。

三种解法：

| 解法 | 做法 | 评价 |
|---|---|---|
| ① 给歌词加"阅读底" | 激活行加不透明背景 | 最省事，但与"沉浸、无卡片"的设计基调冲突（T4d 刻意去掉了卡片底色） |
| ② 频谱让出中段 | 用 `mask-image` 在垂直中段做透明渐变 | 曲线变成"上下两段"，形态被破坏；且歌词滚动时视觉重心乱跑 |
| ③ **频谱移出歌词列**（推荐） | 频谱只在左列信息区（封面背后 / 封面下方），或作为页面底部的窄条带 | 职责清晰：左列是"视觉舞台"，右列是"阅读区"，两者不抢 |

③ 的两种落法，建议都做、由风格设置选：

- **光环式**：频谱作为封面背后的径向呼吸（`radial` 形态天然适配），封面本身是舞台
  中心。左列视觉重量足，右列纯净。
- **条带式**：页面底部一条高 96–120px 的横向山形/镜像带，横跨整页，但**不与歌词
  重叠**（歌词区底部留出这个高度）。保留"线"的形态，又让开阅读区。

`wave`（心电图，2026-10-30 已退役、席位由 `ripple` 接管）形态本就锐利，适合条带式；
`mirror` 适合光环式；`radial` 只适合光环式。
这个映射可以直接写进 `spectrumStyle` 的语义，而不是让用户盲选。

## §6 方向五：设置项拆分

### 6.1 现状

`AppSettings` 只有一个 `spectrum: boolean`，同时控制：

- 是否订阅引擎 tap（`spectrum_set`）
- 背景环境光是否渲染（`AmbientBackdrop` 的 `spectrumOn`）
- 正在播放页是否渲染（`NowPlayingView` 派生的 `spectrumSource`，外加
  `spectrumStyle === 'off'` 这个**第二个**关闭入口）

两个关闭入口语义重叠（`spectrum=false` 与 `spectrumStyle='off'` 都等于"本页不画"），
这是历史叠加的产物（docs/26 补遗 366710c）。

### 6.2 目标形状

```ts
glEffects: boolean;       // 全局 3D/GL 效果总开关（用户 2026-10-30 加）
bgSpectrum: boolean;      // 背景动态频谱（山形环境光）
npSpectrum: boolean;      // 正在播放页频谱
spectrumStyle: 'mirror' | 'radial' | 'ripple';  // 形态；'off' 退役由 npSpectrum 接管，'wave' 退役由 ripple 接管
ridgeGlow: 'soft' | 'balanced' | 'neon';       // 光晕档位（§3.2）
```

**2026-10-30 第二轮删减**（用户拍板）：

- `glass` **删除**：它从加上那天起就没有消费方（CSS 里没有 `backdrop-filter`，
  P3 还没做），打开/关闭视觉上零差异。以后 P3 实现毛玻璃时**不提供开关**，
  默认就是玻璃、低端机自动降级 —— 不做两版差分。
- `density` **删除**：列表密度没有实际价值，只留一套行高（`--row-h: 52px`）。
  `data-density` 属性、tokens.css 的三档变量、look.ts 的读写全部移除。
- `ambient` 的 **UI 文案改为「主题颜色」**，去掉"不跟随封面"的说明 ——
  跟着封面走的旧实现（`accentFromArtwork`）在代码里已经不存在，没有可保留的档位。

`glEffects` 是**总闸**，语义要写死（实现时按这张表判，别在组件里各自解释）：

| glEffects | 结果 |
|---|---|
| `true` | 流动渐变、山形 shader、页面频谱按各自开关工作 |
| `false` | **所有 WebGL 层不渲染、不创建上下文**；背景退回 `--ambient-bg` 静态渐变；`bgSpectrum` / `npSpectrum` 的值保留但无效；**玻璃照常**（玻璃是 CSS 合成，不是 GL） |

注意它和 `bgSpectrum` 的关系不是"嵌套开关"而是"能力闸门"：`glEffects=false` 时即使
`bgSpectrum=true` 也不画。UI 上要做成"关闭后其余频谱项置灰 + hint 说明"，否则用户会
以为开关坏了。

`spectrum` 键**停写停读**，沿用本仓的淘汰惯例（`spectrumEngine` / `accentFromArtwork`
的先例）：旧 blob 里的值经 `mergeSettings` 默认值兜底，`passthrough` 不报错。

迁移规则（一次性，读旧值时）：

```
bgSpectrum = 旧 spectrum
npSpectrum = 旧 spectrum && 旧 spectrumStyle !== 'off'
glEffects  = true      // 新键缺失时默认开
glass      = true
ridgeGlow  = 'balanced'
```

tap 开关由二者派生：`shouldTap = glEffects && (bgSpectrum || npSpectrum)`。数据层不用改——
`RemoteSpectrumSource` 的引用计数已经处理"两个消费方只开一个"。

——本仓设置页的 hint 一直是这个写法。

## §7 技术架构：一个上下文，一个调度器

三条硬约束决定架构：

1. **WebGL 上下文有数量上限**（Chromium 16 个，超了丢最老的）。背景层、
   正在播放页、未来可能的更多可视化，**必须共享一个 `WebGLRenderer` + 一个 canvas**。
2. **rAF 只能有一个**（docs/26 踩过 `2^n` 调度的坑：每帧多排一个下一帧，几秒内主线程
   被淹没、UI 假死）。多层绘制要挂在同一个调度器上。
3. **必须能降级**。§2.3 的软件光栅结果说明 Canvas 2D 路径不是"安全牌"，但 WebGL
   在无 GPU 机器上同样不可用——所以要有能力探测，探测失败就**关掉动态层，回到静态渐变**
   （而不是回到 Canvas 2D）。现有 Canvas 2D 实现保留为第二档降级。

```
lib/render/
  context.ts    单例 WebGLRenderer + 尺寸/DPR 管理 + contextlost 重建 + 能力探测
  scheduler.ts  单 rAF 多订阅者（每层注册 draw(now)，一帧只排一次 next frame）
  layers/
    flow.ts     流动渐变（1 全屏 pass）
    ridge.ts    山形 + 光晕（1 全屏 pass，48→256 重采样在 CPU）
    lines.ts    正在播放页三形态（1 全屏 pass）
```

能力探测（`context.ts`）：

```
1. canvas.getContext('webgl2') 为 null          → 降级档 0（静态渐变，无动态层）
2. UNMASKED_RENDERER 含 SwiftShader / Basic Render Driver / llvmpipe
                                               → 降级档 0
3. 其余                                        → 正常（WebGL）
```

另加两条运行期保护：

- `webglcontextlost` → 停止调度、重建一次、失败则降级档 0（不弹错，静默降风格）。
- 页面隐藏（`document.hidden`）→ 暂停调度（现在两个组件的 rAF 在后台仍跑，
  Chromium 会节流但仍在算）。

`prefers-reduced-motion: reduce` → 档 0（现有行为保持）。

### P1 背景流动渐变 —— ✅ 已落地（2026-10-30）

新增两个文件：

| 文件 | 职责 |
|---|---|
| `ui/src/lib/render/context.ts` | `GlStage`：全应用唯一 renderer，管尺寸 / DPR / 上下文丢失 / 图层顺序 |
| `ui/src/lib/render/layers/flow.ts` | 流动渐变图层：3 octave fbm + 域扭曲，时间系数 0.06 |

**两层结构**（这是本批唯一的架构决定）：场在 `384×216` 的 render target 上算，
**每 90ms 一次**；全分辨率每帧只做一次纹理采样 + 抖动。依据是"变化量是否可辨"
而不是"省多少"——时间系数 0.06 下 90ms 内场的位移约 0.0054 个噪声周期，远小于
1 个色阶，逐帧更新看不出差别。时间系数与频率（1.6）都写进 shader 注释，
调参时能看出它们之间的关系。

颜色**不硬编码**：主色取 `--accent`，副色由主色 `offsetHSL(+0.09, +0.02, +0.08)`
得到。加第 6 套配色时这里零改动——硬编码 5 组颜色的话，新方案会静默用错色，
而且没人会发现（themeColor 已经有缓存与 MutationObserver 失效信号，直接复用）。

验收（`tools/bench/verify-flow.mjs`，三轮共 10 项，全 PASS）：

- 切 5 套方案，GL 画布平均色相分别为蓝 / 橙 / 绿 / 紫 / 白（读 `readPixels` 统计）
- `flow ON` 时右边缘竖带 5s 平均差 `meanΔ=0.21`（在动）；`flow OFF` 时 `meanΔ=0.000`
  （**完全静止**）—— 负向对照，若关掉还在动说明开关没接上
- 帧间隔（1280×800，vsync 不解除）：开 `p95=16.9ms` / 关 `p95=16.8ms`，
  60fps 两态一致，超出预算 0.1ms < 0.2ms
- `reducedMotion: 'reduce'` → 画布**根本不创建**（不是"动得慢一点"）
- 软件光栅（`--disable-gpu`，探测到 SwiftShader → 档 1）→ 画布不创建、静态渐变仍在、无报错
- 真 Tauri 窗口（1756×1050 @DPR1.75，drawing buffer 3073×1837）：`Page.captureScreenshot`
  回读正常，背景光雾正确叠在 CSS 渐变之上、**没有黑底/矩形断裂**

三个坑（都会重犯，写下来）：

1. **`AdditiveBlending` 会把预乘色再乘一次 alpha**。three 的 `AdditiveBlending` 是
   `(SRC_ALPHA, ONE)`，而着色器输出的是预乘色 `(col*alpha, alpha)` → 等于乘了平方。
   实测云团最亮处 rgb 只剩 **1/255**，画面接近全黑（只剩 alpha 在加，视觉上"什么都没画"）。
   预乘加色必须用 `CustomBlending` + `(ONE, ONE)`；浅色主题的 over 合成是 `(ONE, ONE_MINUS_SRC_ALPHA)`。
   判断依据不是看代码，是 `gl.readPixels` 读 max rgb —— 肉眼看截图会以为是"强度调太低了"。
2. **`THREE.Color` 存的是线性值，画布按 sRGB 解释**。直接把 `Color` 送进 shader 输出，
   整体会偏暗、两色过渡中段发灰。着色器末尾要 `lin2srgb()`，且**混色在线性空间做**。
3. **能力档位要在"渲染 canvas 元素"这一层判，不能只在 `createGlStage` 里判**。
   后者返回 null 时 `bind:this` 已经把画布渲染出来了，留下一个全屏透明画布白占一层合成
   （软件光栅那轮实测就是这样：档 1、但 `canvas.ambient-flow` 还在）。

`glEffects` 关掉时连 `GlStage` 都不建（`AmbientBackdrop` 的 `glOn` 已含闸门与档位判断），
不是"建了但不画"——上下文名额是稀缺资源，不用的不占。

**P1 第二轮：fbm 换成纯晕染（2026-10-30 用户反馈"有色块和尖角"）**

fbm 那条路的结局是注定的：`smoothstep` 是阈值，阈值处一阶导不连续，暗背景上
一定读得出边缘；再叠一层域扭曲（把噪声坐标按另一路噪声偏移），坐标本身被拉出
折角。加大遮罩范围只能把边缘摊平一点，不会让它消失。

现在换成 5 个**椭圆高斯斑叠加**：

```
s = Σ wᵢ · exp(-1.35 · |(p - cᵢ(t)) / rᵢ|²)
α = (1 - exp(-1.05 s)) · intensity
```

三个关键点：

1. `exp(-r²)` 处处可导 —— 没有阈值就没有边缘，也没有"形状"可读，只有浓淡。
2. 半径给得大（0.24–0.45 视口）、相邻斑**始终重叠**。一旦两个斑分开，边缘就会
   读出"两个圆"，那又变回形状了。
3. 饱和用 `1 - exp(-k·s)` 而不是 `clamp` —— clamp 在超限处压出一条等值线，
   极暗背景上能看见。

副产品：比 fbm 便宜（5 次 `exp` vs 12 次噪声取样），也不再有 octave 网格。

坐标从"几个噪声周期"改成 uv 的 0–1（位置写"屏幕的百分之几"），光斑半径的 x 分量
除以 `uAspect`，否则宽屏上会被拉成横条。

**P2 实测修正（2026-10-30，落地后第一轮视觉反馈）**

首版有一个符号错误，而它正好表现为"背景亮度太高"：

```
float dN = (vUv.y - hN) * uHeightPx;   // 错：d>0 变成"脊线以上"
```

原 Canvas 2D 是 `moveTo(0,BH) → 曲线 → lineTo(BW,BH) → close()`，山体从**底边**
升到脊线。shader 里 `vUv.y - h` 让 `d>0` 落在脊线**上方**，于是整片上半屏被实色
填充盖住，山脊反倒成了"天空的下边界"。视觉上就是背景被抬高了一整档。

改成 `(h - vUv.y)` 后，同一曲、同一相位的整屏平均亮度：

| 形态 | 平均亮度 (0–255) | 说明 |
|---|---|---|
| 只留 CSS 渐变（`bgSpectrum=false`） | **33.6** | 参考下界 |
| 动态层开，方向修好 + 柔雾档 | **38.1** | 比下界高 4.5 |
| 动态层开，方向修好 + 平衡 / 锐光 | 40.1 / 42.8 | 光晕只占 2–5 |
| 动态层开，**方向错的**版本 | 58.1 | 比下界高 24.5 ← 用户看到的"太亮" |

⚠️ 上表是**暂停**状态测的（山形贴底，只占很小面积），只能用来比较"方向"。
播放中、山形填满下半屏时另测一组（苔原主题，行高 52px，2560 宽窗口）：

| 形态 | 平均亮度 |
|---|---|
| 只留 CSS 渐变 | 44.3 |
| + 柔雾 / 平衡 / 锐光 | 52.1 / 54.9 / **58.1** |
| 六秒画面差（验证在动） | meanΔ 2.3，14.2% 像素有变化 |

**主题颜色本身决定了下界**：极光（蓝）33.6，苔原（绿）44.3 —— 绿色在 Rec.709
的权重是 0.7152，同样"看起来不亮"的绿，测出来比蓝高一档。判断"是不是太亮"
必须和同主题的下界比，不能跨主题横向比。

结论：**过亮不是光晕造成的，是填充方向错了**。光晕三档之间只差 2.7，属于
"脊线清晰度"的差别；真正决定整屏亮度的是填充覆盖的面积。

顺带把系数整体下调（原三档在方向修正后仍偏亮），`soft` 现在是**纯填充、
三层光归零**——就是"解除光晕"的形态：

| 档 | bodyNear/Far | rim | glow | halo |
|---|---|---|---|---|
| 柔雾 | 0.30 / 0.24 | 0 | 0 | 0 |
| 平衡 | 0.30 / 0.24 | 0.06 | 0.05 | 0.03 |
| 锐光 | 0.28 / 0.22 | 0.28 | 0.18 | 0.08 |

流动渐变强度同步降到 `dark 0.12 / light 0.075`（原 0.26 / 0.16）；它全屏
加色叠加，是仅次于填充的第二个提亮源。

复跑：`node tools/bench/imgstat.mjs <png...>` 只统计中段区域（避开标题栏与
播放条），给出 mean / max / 8 段直方图 —— 亮度这种事必须落成数字，肉眼在
"深蓝"和"深蓝再亮一点"之间分辨不了。

P2 另外两个坑：

1. **GLSL 源码是模板字符串，注释里不能出现反引号**。写了一句
   `` 写成 `vUv.y - h` 会…`` 直接把字符串截断，vite 报 `PARSE_ERROR` 且错误
   定位在注释行（看起来像语法问题，其实是字符串提前结束）。GLSL 里的注释只能
   用普通文字描述变量名。
2. **"看起来像山"不足以验证方向**。首版截图里确实有起伏曲线、有光晕，
   我据此判定 P2 通过；但山体填在了脊线以上 —— 形状对、位置反了。
   这类错误的判据不是"有没有形状"，而是**"填充在脊线的哪一侧"**：
   正确形态是山体从底边升起、越靠底越淡（对应原 Canvas 的
   `moveTo(0,BH) → lineTo(BW,BH)`）。以后验任何"从底部升起"的图形，
   都先确认填充落在下侧、且顶部区域是透的。

**P2 第三轮：低频竖直色带（2026-10-30 用户反馈）**

两处都是"高度"这个标量在**横向**上的不连续造成的：

1. **高度纹理原来是 8bit**。1/255 的量化在 800px 高的画布上是 3px 台阶，
   台阶侧壁竖直、只有 1.5px 抗锯齿 —— 低频带剧烈起伏时会排出一列竖线。
   改用 `HalfFloatType`（R16F）：10 位尾数，步进约 0.8px。**不能选 R32F** ——
   它在 WebGL2 里不可线性过滤（要 `OES_texture_float_linear`），而山脊必须靠
   线性过滤才不会显出 256 段折线；R16F 是 core 保证可过滤的。
2. **带与带之间没有横向关系**。低频几个带能量大、各自独立跳动，同时冲高时会在
   山脊上留下又陡又窄的孤立尖峰（两支之间只有 5px 左右，放大后读作"竖线"）。
   加了带域平滑 `[0.22, 0.56, 0.22]`：只削孤立峰（约 44%），宽峰几乎不动，
   峰谷**位置**不变 —— 山形的起伏节奏仍是原来的。

顺带记一条：设置页截图里的"竖条纹"其实是**面板半透明 + 背景叠加的采样痕迹**，
不是山形。验证渲染问题必须裁到无面板遮挡的区域（正在播放页）再看，否则会把
UI 的合成伪影当成渲染 bug。

   现在反过来：频谱全宽照画（mask 撤掉），对比度交给**当前句底下的一块
   渐隐暗雾**。这块衬底改过三版，留档：

   **v1（当天先做，随后被推翻）**：`.np-lyrics::before` + `:has(.lyric-line.active)`
   门控，椭圆钉在容器正中。它只靠"激活行总被滚到中线"这条约定**间接**对上位置：
   smooth 滚动没落定时、用户手动滚走后，椭圆停在原地而当前句早走了 —— 用户反馈
   "做成真元素，让它跟大字一起出现"。

   **v2（现行）**：`.lyric-halo` 是**当前句自己的子元素**（LyricsPanel 里
   `{#if index === activeIndex}` 渲染），跟着这一行滚、跟着它换行。三个要点：

   - 层序：`z-index: -1`，且**故意不给这一行加 `isolation`**。激活行本身不是
     层叠上下文（opacity 1、无 transform），衬底于是冒泡到 `.np-lyrics`
     （`position:relative; z-index:1`）里、排在**所有文字之下**。
     如果加 `isolation: isolate` 把衬底关在行内，整行会变成 z-index:0 的层叠
     上下文，连衬底一起抬到上下相邻的歌词行**之上**，把邻句文字压暗。
   **v3（定版）**：形状与量级重调，衬底终于不显脏。三处改动：

   - 尺寸：`width: 100%`（原 118% 会左右各探出一截，读成一条横带）、
     `height: 124px`（原 200px 纵向铺太开，上半截糊到上一句上）。
   - 衰减：`0% → 24% → 46% → 68% → 88%` 依次 `100/65/32/11/0`，88% 才收干。
     早先的 `0→40%(68%)→80%(透明)` 中心一大片实色，边界一眼可见，整团像膏体。
     实测水平亮度剖面单调递减、无拐点。
   - `filter: blur(14px)`：渐变椭圆的弧是数学曲线，肉眼对弧线极敏感。模糊
     把最后那点弧度抹平，才读成"一层雾压在这儿"而不是"一块椭圆"。

   颜色又试过一版**白光**（同一套形状参数，`rgba(255,255,255,.8)` 托底），
   当场被否：深色背景上白光变成一条发光横带，且白字压白光对比度掉到
   2.1–2.3:1。定版回到黑色 `rgba(0,0,0,.92)`（亮色 `rgba(20,30,60,.24)`）。
   **黑色不能照搬白光那版的参数**（衰减到 95% + blur 22）：黑色是减法，被
   摊薄后压暗量只剩 3–4 个灰阶，等于没画。给的这套是实测能看见压暗、
   边缘又干净的值。

   层序验证（定版实测）：把衬底隐藏前后做像素对比，激活行字形像素平均亮度
   差 3.55、衬底区字形差 4.61（噪声级），只有背景在变 —— 文字没被压。

   注意：衬底在 `.lyrics-body` 内，会吃它的上下 10% mask —— 当前句被滚到
   边缘时椭圆的下缘（或上缘）会跟着淡出。这是对的：那一行的文字也在淡出。

验收：960×600 与 2560×1440 两个尺寸下：封面不溢出、信息块不与封面重叠、
歌词行宽 ≤ 26em、返回后滚动位置不丢。

#### P5 之一：尺寸跟随修复 + 波形换血（2026-10-30 落地）

**① 尺寸不跟随（真 bug）**。`NowPlayingSpectrum` 每帧判断要不要重分配 backing
store，条件只写了宽度：

```ts
if (target.width !== Math.round(width * dpr)) { target.width = ...; target.height = ...; }
```

于是窗口**只在纵向**变大（最大化只改高度、分屏、拖下沿）时 `height` 属性留在旧值，
浏览器把旧位图纵向拉伸 —— 观感正是"图表不跟页面尺寸重绘/重定位"。背景层走 WebGL
渲染器（有自己的 resize 回调）所以正常，两相对比更明显。修法：宽、高各自比，
并加 `ResizeObserver` 只更新 CSS 尺寸缓存（绘制循环不再逐帧读 `clientWidth`，
把绘制和布局解绑）；DPR 每帧重算，拖到不同缩放比的显示器也能跟上。
实测（WebView2，DPR 1.75）：`2065×1582 @css 1180×904` → 视口改 980×620 后
`980×474 @css 980×474`，恢复后回到 `2065×1582`。

**② `wave`（心电图）退役**。它的折线密度由**频带数**决定（48 个 R 波挤在同一宽度），
低频能量高时相邻峰连成一片尖刺、高频段又拉成锯齿，观感就是"幅度算错了"。
形态本身没有可救的参数（是密度和宽度的矛盾），直接让位。

**③ `ripple`（波纹地形）接手**。方法取自工作区 `JS波纹/`（MKVDB 2016 Minimal
Wavescape，WebGL 噪声壁纸），核心是**不画有起伏的面，而是沿视线方向一层层画
"等深线"**：那个 shader 在每个深度 z 只画 \|Δy\| < 0.0025 的像素，16 层叠起来因透视
向下发散，亮度按 `exp(-0.3r)` 随深度衰减。这里保留骨架、换掉高度函数：

- 高度 = 频谱本身。48 带当一条横向曲线（带间线性插值），每层取一个平移位
  （`l * 1.35` 带）→ 相邻层峰谷错开，读成"波纹斜着淌"；外加 `t * 2.6` 缓慢漂移。
- 位置走透视的二维等价：`base = horizon + span * k^1.55`（k 为层序号 0→1），
  远处挤在地平线附近、近处拉开。严格针孔投影只会把线推出画布，没有额外收益。
- 振幅/线宽/透明度随 k 递增，再按整体能量缩放（安静段浪低、副歌抬起来）。
- 地平线放在页高 60%：上方留给歌词与封面，波纹只铺下半屏。
- 光晕只给 k > 0.55 的近层（22 层全开 shadowBlur = 每帧 22 次模糊，远处细线也
  看不出光晕）。实测帧间隔中位 16.6ms / p95 17.2ms / max 18.9ms（60fps 稳）。

迁移：`'wave'` 在 `mergeSettings` 里**显式映射**到 `'ripple'`（在形态白名单
检查之前）——用户当初选的就是"折线感"，落回镜像等于替他改选择。存量 `'off'`
仍按"不在白名单即落默认"消化。

#### P5 之二：背景波纹图层（WebGL，2026-10-30 落地）

同一天后半段：波纹从"页内主视觉"再推广到**背景**——同一套画法在 GL 里重写一遍
（`lib/render/layers/ripple.ts`），与 `RidgeLayer` / `FlowLayer` 共用单例 `GlStage`，
**不新增 canvas、不新增 rAF**（§7 的两条硬约束）。

- **为什么重写而不是复用 2D 版**：2D 版每层一次 `shadowBlur`，全窗口尺寸下就是
  每帧二十几次高斯模糊；GL 里到线的像素距离在 fragment 里本来就有，光晕是它的
  指数衰减，一次 pass 画完，层数也能更多而不心疼。
- **曲线来源**：`RidgeCurve`（与山形共用同一套 48 带 → 256 点平滑重采样），但
  两端各 12% 用 smoothstep 窗压向静息值。层间平移是**循环采样**，而曲线不是周期
  函数（带 0 与带 47 无关），不环形化就会在某处出现一条竖直断裂缝，缝还随漂移
  移到屏幕中间。静息值取 `均值 * 0.5` 而不是 0：压到 0 会在两侧留下贴地的死
  水平线，比断裂更显眼。
- **与山形的关系**：同一舞台、同一份曲线思路，但**不是同一图层**——山形是闭合
  填充（实形），波纹是线（光、低 alpha）。由 `bgSpectrumStyle` 二选一，切形态时
  整层重建（几何结构不同，不像光晕档位那样只改 uniform）。
- **参数**：22 层；`base = uHorizon - uSpan * k^1.55`；每层横向平移 2.6 带、整体
  漂移 0.55 带/秒（层间错位要"看得出斜淌"，又不能大到相邻层完全无关——那会散成
  噪声）；振幅/线宽/透明度随 k 递增，再按整体能量缩放；`uHorizon` / `uSpan` =
  0.40、`uGain` = 0.72（背景是氛围，不能比列表文字亮）。
  横向包络 `0.62 + 0.38 * sin(x * 2π * 1.25 + l * 1.7 + t * 0.4)` 是**必需的**：
  只有整体平移时，22 条线是"一族等高、等距、仅错位"的平行条纹，读成条形码；
  包络让波峰沿 x 起伏，层与层才会交叉成水面。相位必须带层号，否则只是同一条
  曲线平移十七次。
- **地平线淡出**：最远那层振幅最小、几乎是条水平直线，直接出现会在地平线拉出
  一道亮边（像"水面被一条横线封住"）。加
  `1.0 - smoothstep(uHorizon - 0.05, uHorizon, vUv.y)` 让它从暗处浮出来。写成
  `1 - smoothstep(小, 大)` 而不是 `smoothstep(大, 小)`：GLSL 规定 edge0 >= edge1
  时结果**未定义**，反着传在部分驱动上是随机值。

**设置与迁移**：`bgSpectrumStyle` 与页内 `spectrumStyle` **刻意分开**——背景是
常驻氛围、页内是一次性聚焦，共用一个键会让用户为了页内试形态而改掉背景。非法值
落回 `ridge`；页内形态不串到背景。设置页在"波纹"时把"山形光晕"置灰（那是山形
专用的 uniform，对波纹无意义）。

#### P5 之三：页内波纹降为单线（2026-10-30 定版）

背景有了地形之后，页内那份地形就成了**同一屏两片水**：内容层被夹在中间；而且
页内 canvas 是 `inset:0` 覆盖内容区（`.now-playing-page` 限宽 1180），水面到画布
边缘就断，和背景那片铺满窗口的地形既重复又不同源。

用户拍板：页内三形态不变，`ripple` 从"22 层地形"降为**一条居中曲线**——背景负责
场面，页内只留主视觉。实现（`NowPlayingSpectrum.drawRipple`）：

- 48 带按"带"为单位浮点采样（循环 + 线性插值）。按数组下标取会在带边界折角，
  48 个点在 1180px 宽上就是 48 个硬拐点；采样后再走中点二次贝塞尔，拐点才圆。
- 缓慢横移 0.35 带/秒：线像水面一样淌。再快就退回"左右抖动的心电图"，那正是
  `wave` 退役的原因。
- `amp = height * 0.115 * (0.45 + 0.55 * energy)`：以**画布高度**为基准——宽度只
  影响采样密度，不该让线变陡。能量下限 0.45 保证静音时不会塌成一条直线（那样
  看着像画错了），上限才抬浪。
- 描边参数与镜像对齐（1.8px、`shadowBlur` 16、accent 渐变左右各 7% 淡出），
  形态切换时亮度不跳。**不做填充**：镜像靠上下两条曲线的间距读音量，单线只有
  高度一个自由度，填充只会把中间那句歌词压成灰底。
- 设置页标签由"波纹地形"改为"中轴波纹"（`SPECTRUM_STYLES`）；取值 id 仍是
  `ripple`，不动迁移。

#### P5 之四：光效归一 + 暂停语义（2026-10-30 收尾轮）

用户提两条收敛要求，外加一次"这一轮改动太多"的回审。

**① 两种背景形态共用"背景频谱光效"**。原先这一档只喂给山形的 shader，波纹固定
一套参数，设置页在波纹时把该行置灰。现在两层共用 `ridgeGlow`，判据统一成
"光的多少 + 边缘的锐度"（`RippleLayer` 的 `GLOW_PRESETS`）：

| 档位 | 山形 | 波纹 |
|---|---|---|
| 柔雾 | 三层光全部归零，只有填充 | 光晕归零，线加宽 1.35×、略压暗 → 只有线，没有光 |
| 平衡 | rim .03 / glow .025 / halo .015 | 近层光晕 0.18、半径 9px，线宽原样 |
| 锐光 | rim .28 / glow .18 / halo .08 | 线收细 0.72×、提亮 1.18×，光晕 0.34、半径收到 6.4px |

键名仍叫 `ridgeGlow`（先有山形，改名要动迁移，不值）。设置页那一行不再按形态
置灰，hint 改成"山形与波纹共用这一档"。

实测（真窗口 1600×1000，波纹形态，播放中；A/B/A 控噪声，取背景区平均亮度）：
柔雾 **34.2 / 34.1**（同档两次差 0.1 = 噪声），平衡 **36.3**（+2.1），锐光 **37.3**（+3.1）。
单调且远超噪声，说明三档真的作用在波纹上。

**② 暂停 = 静止 + 收平，不暂存状态**（用户原话："所有频谱都应该暂停时拉平，
不暂存状态"）。三个图层加同一套语义：

- `gate`：暂停时按 70ms 时间常数淡到 0，约四帧收平。**不硬切**（硬切像渲染挂了），
  但会一次收干净，不保留暂停前的峰谷；
- 冻结各自的时钟：`RippleLayer` 用内部 `clock`（只在播放时 `+= dt`），页内 canvas
  同理，于是波纹不再横移、环形不再慢转；
- 暂停时喂**全 0** 而不是"停住上一帧"：曲线自身衰减 + `gate` 双保险，恢复播放时
  从 0 重新长起来（不接旧状态）。
- 山形不喂 0 的话会停在暂停前的高度上（就是"凝固的浪"），所以这条对山形同样必须。

实测：页内 canvas 的曲线纵向展开（spread）播放 **52px** → 暂停 **0px** → 恢复 **50px**；
暂停期间相邻两帧整张位图**字节差 0**（完全冻结）。背景波纹暂停后只剩水平直线。

**③ 回审发现并修掉的三处**（都不是新写的功能，是这一轮欠下的债）：

- **页内频谱没挂共享调度器**：它自排 `requestAnimationFrame` 并自我续帧，于是
  "背景层 + 页内"同时存在两个循环，违反 §7 第 2 条。改 `subscribeRender(draw)`，
  顺带把"每帧 ×0.25"的时间平滑换成 dt 形式（144Hz 上不再跟得太急）。
- **2D 兜底路径也有"只比宽度"的同一个 bug**（`AmbientBackdrop` 主画布）：窗口只在
  纵向变大时旧位图被拉伸。宽高各自比。
- **`RETIRED_KEYS` 漏了 `density` / `glass`**：`mergeSettings` 把 raw 里的未知键原样
  带进结果，而写回是 `setSettings(整个 settings)`，于是这两个死键会跟着每次改设置
  永久写回磁盘——正是本文件"停写要真停"那条约定要防的情况。

| three 体积 +126KB gzip | 本地应用影响小，但不可逆 | 接受；若只想做 2D 光晕，原生 WebGL2 约 80 行、零依赖——这是唯一值得回头的岔路 |
| 玻璃在 4K + 低端核显 | 帧率明显掉 | **已规避**：P3 改判为"壳层不上玻璃"，只有瞬时浮层（Dialog/Menu/Popover/Select）付钱，背景动画不再触发全屏重模糊 |
| 多消费方共享 renderer 的尺寸管理 | 覆盖层与全窗口尺寸不同 | **已定**（P1）：唯一 canvas + 唯一 renderer，图层按 `add()` 顺序同帧依次画；需要不同分辨率的图层（如流动渐变）自己开 render target，不动主 buffer |
| 设置键迁移写错 | 用户配置丢失 | 迁移只读不改写旧键；新键缺失时按 §6.2 派生；单测覆盖三种旧组合 |

未决（需要用户拍板）：

1. 光晕档位默认值 —— **已定 `balanced`**（2026-10-30）。三档只改 shader 衰减系数，
   成本无差别，属纯审美，随时可改。
2. 正在播放页频谱：光环式还是条带式 —— **已结**：都不做。三形态（镜像曲线 /
   径向环形 / 中轴波纹）保留，`ripple` 在页内是**一条居中曲线**，地形只留给背景
   （§P5 之二/之三）。
3. 流动渐变是否要独立开关 —— **仍未决**，当前跟随 `bgSpectrum`（§6.2 的
   `shouldTap = glEffects && (bgSpectrum || npSpectrum)`）。

已定（2026-10-30）：正在播放页**不叠覆盖层**，改为侧栏退出、全应用单一背景（§5.2）；
标题栏保留（窗口按钮在那）；新增 `glEffects` 全局 3D 总闸（§6.2）。

## §10 复现方式

```bash
# 全场景 × DPR1/2（headed，真 GPU）
node tools/bench/collect.mjs

# 单个维度
node tools/bench/collect.mjs --dprs=2 --vw=1920 --vh=1080 --scenes=canvas,canvas-overlay

# 软件光栅（模拟无 GPU；慢，把测量窗口压到 1.5s）
node tools/bench/collect.mjs --soft --dprs=1 --scenes=webgl --ms=1500 --timeout=120000

# 视觉校验（截图落到 tools/bench/shots/）
node tools/bench/shot.mjs
```

`--vsync` 可切回真实 vsync 模式（用于"能否稳 60"的验证，而不是成本对比）。
