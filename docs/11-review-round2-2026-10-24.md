## 二、P0 — 功能性断裂（5 项，逐项人工复核）

### P0-1 ★ 播放进度永不推进：进度条钉在 0:00，位置永不落库
- **位置**：`src-tauri/src/lib.rs:1692-1705`；根因在 `crates/aiya-player/src/actor.rs:87`
- **机制**：
  ```rust
  // actor.rs:87 —— state() 每次调用都重建，updated_at 是"此刻"
  updated_at: now_ms(),
  // lib.rs:1695
  let last = actor.state().updated_at;   // = 现在
  let now_ms = SystemTime::now()...;     // = 现在 + 几十微秒
  if now_ms >= last + 500 {              // 恒为 false
  ```
  节流基准取的是"刚生成的时间戳"，永远差不到 500ms。于是 `PlayerCommand::Position` 从不归约，`should_emit` 从不被置位。
- **后果链**：① `PlayerBar` 直读 `player.positionMs`，进度条与时间文本全程冻结；② 泵里 5s 节流落库写的是同一份冻结值 → **"记住播放进度"实际存的是装载点**；③ `updatedAt` 失去乱序丢弃语义；④ 歌词面板只在 prop 变化时重锚。
- **为何 81 个测试全绿**：actor 单测直接 `reduce(Position{...})` 绕过节流；事件泵是 async task，宿主层 0 测试。
- **修法**：节流基准改用泵局部变量 `last_emit_ms`（已有的 `last_position_ms` 就是这个用途），不要从 `state()` 取。

### P0-2 ★ 选中任意行后点批量操作，后端死循环，整个 App 冻结
- **位置**：`ui/src/App.svelte:144-156`（`currentQuery()` 恒 `mode:'offset'`）→ `lib.rs:601-612` → `crates/aiya-data/src/repo.rs:340-355,402`
- **机制**：`library_ids_for_selection` 用 `loop` 逐页拉全量，推进手段是 `q.cursor = Some(c)`；但 UI 传的 query 是 **offset 模式**，`list_tracks` 在 offset 模式下只读 `q.offset`（`repo.rs:354`），`cursor` 被完全忽略。每轮返回同一页前 500 条，而 `next_cursor` 因 `has_more && key_expr(q).is_some()` 恒有值 → 循环永不退出，`ids_out` 无限增长。
- **后果**：唯一的 DB 线程被永久占用，`library_list`/`library_stats`/`fetch_track_refs` 全部排队，界面整体卡死并持续吃内存。
- **触发条件**：曲库 >500 首，点中任一行让批量栏出现 → 点「播放/加入队列/移除」。**日常路径**。
- **为何没抓到**：mock 的 `idsForSelection` 忽略 mode 全量切片，浏览器预览永远正常。
- **修法**：命令侧不信上游 mode（`mode: Cursor, cursor: None, offset: None`）+ 页数硬上限；UI 另建 `selectionQuery()`。

### P0-3 ★ 歌单的改名/删除/清空/加歌/删歌/排序全部静默失败
- **位置**：`ui/src/compat/api.ts:112-119` 调 7 条命令；`lib.rs:1798-1846` 的 `generate_handler!` 只有 `playlist_list/detail/create`（`grep -n "fn playlist_"` 仅 4 个）
- **机制**：`invoke('playlist_rename')` 在 Tauri 层直接 reject（command not found），不是 `fail()` 信封；而 `ui.svelte.ts:153-193` 这 7 个方法**没有 try/catch**，调用方只判 `result.ok` → promise 直接 reject，连"失败提示"都走不到。
- **用户感知**：右键重命名/清空/删除、批量"添加到播放列表"、歌单内拖拽排序 —— 对话框关闭、什么都没发生、无任何提示。
- **为何没抓到**：mock 里这 7 条命令全都实现了（`mock.ts:348-401`），预览一切正常。
- **修法**：补 7 条 Rust 命令（含 `playlist_items.position` 重排）；过渡期至少把 reject 转成 `E_NOT_IMPLEMENTED`。

### P0-4 ★ beets stdio 未钉死 UTF-8：中文路径/中文标题全链路失效
- **位置**：`sidecar/beets_sidecar.py:87,450,501`（直接写 `sys.stdout` / 读 `sys.stdin`）；`src-tauri/src/beets.rs:318-322,701`（只注入 `BEETSDIR`，无 `PYTHONIOENCODING`）；`beets.rs:360`（`lines()` 失败即 `break`）
- **机制**：Windows 下 Python stdio 被管道重定向时用 **locale 编码（cp936）**。Rust 写 UTF-8 字节 → Python 按 GBK 解 → 路径变乱码 → `Item.from_path` FileNotFoundError；Python 按 GBK 写出 → Rust `BufReader::lines()` 报 `InvalidData` → 管道线程**静默退出且不发任何终止事件**。
- **复核**：全仓库生产代码无 `PYTHONIOENCODING` / `PYTHONUTF8` / `reconfigure`（已 grep 确认）。
- **触发条件**：任何非 ASCII 路径/专辑名；**中文用户名**（`C:\Users\张三` 进入 status 输出）→ 设置页报 `E_BEETS_NOT_FOUND`，让装了 beets 的用户去装 beets。
- **为何 81 个测试全绿**：`tools/smoke_apply.py:31` 显式设了 `PYTHONIOENCODING=utf-8`，正好把这条掩盖掉。
- **修法**：Python 启动即 `sys.stdout.reconfigure(encoding='utf-8', newline='\n')` + `stdin` 同理；Rust 三处 spawn 加 `.env("PYTHONIOENCODING","utf-8")`；读取改 `read_until` + 显式 `from_utf8`，非法字节要上报而非 break。

### P0-5 行聚焦后按空格：同一按键派发两次（重播该行 + 全局播放/暂停）
- **位置**：`ui/src/components/TrackList.svelte:200-206`（行 keydown 只 `preventDefault`，无 `stopPropagation`）+ `App.svelte:607-643`（window 级 Space = playPause）
- **机制**：事件冒泡到 `<svelte:window onkeydown>`，全局处理器只排除输入框 → 同一 tick 发出 `onplay(row.index)`（重播）与 `player.toggle()`（暂停）。
- **触发条件**：点任意行（`tabindex="0"` 即获焦）→ 按空格。**最常见的操作流**。
- **用户感知**：想暂停，结果当前曲从头重载，播放状态取决于两条 invoke 的到达次序。同构问题存在于 `QueuePanel.svelte:186-189`、`LyricsPanel.svelte:122-127`。
- **备注**：旧 Electron 版 Space = 选中，本次改成 Space = 播放才让冲突变成"重播"，属**新引入**。
- **修法**：全局 `if (event.defaultPrevented) return;` 一次修掉三处。
