## 目标与页面结构

将 Liquidsoap 频道管理从直播页拆为应用内的独立一级页面。原直播页只负责
收听，新页面负责频道、歌单与节目表管理，保持现有应用壳与底部播放条。

| 位置 | 入口 | 页面职责 |
|---|---|---|
| 上部内容导航 | 直播 | 流卡浏览、添加地址、收听、移除、本地播放列表入口 |
| 底部工具导航 | Beets | 现有 Beets 功能 |
| 紧邻设置上方 | 推流 / Broadcasting | 频道列表、详情、编辑、歌单、节目表及开停播 |
| 底部末项 | 设置 | 现有设置功能 |

新页面路由使用 `broadcast`，组件为 `BroadcastView.svelte`。原 `live` 路由、
导航名称与收听卡组保留；取消「收听 / 我的频道」双标签。

「推流」按 `backendCaps().streaming` 显示，仅 HTTP/Docker 宿主提供入口。
Tauri 与桌面 mock 不显示；跨宿主恢复到 `broadcast` 时回退到 `live`，避免
恢复出一个不可用页面或发送 station 命令。能力判定沿用现有宿主机制。

## 第二阶段 · 推流配置重设计（已完成）

### 1. 目标与现状依据

本阶段承接三个要求：移除拆页后冗余的标题层和「返回列表」，新建频道改用
模态框；节目安排直接选择系统已有歌单；重新组织频道列表与节目表。

代码核查得到的实施前提：

| 当前实现 | 对重设计的影响 |
|---|---|
| `BroadcastView` 页头之外，`StationPanel` 还有列表标题、详情标题和返回按钮 | 只删除一个标题仍会保留列表 → 详情的切页结构，需要改为频道行下展开配置抽屉 |
| 新建/编辑频道使用 `mode='edit'` 替换整页 | 改为共享 `components/ui/Dialog.svelte`，保留背后的频道上下文 |
| 侧栏歌单使用 `playlists/playlist_items`；频道使用独立的 `station_playlists` | 仅更换下拉选项不能实现复用，服务端取曲与引用关系也需要调整 |
| 系统歌单已有 manual/smart；动态歌单由现有操作物化曲目 | 推流读取已有成员与顺序，不另建规则引擎、不擅自刷新动态规则 |
| 节目表是尺寸较大的 7×24 个按钮；时间读写用 `parseInt`，分钟会丢失 | 缩为紧凑周视图时间选择器，支持框选，保留原始 HH:MM |
| 前端跨午夜按同一日涂格，后端拆成起始日与次日 | 统一跨午夜语义，尤其覆盖周日 → 周一 |
| 频道歌单按位置继承 id，整表删除再插入；节目引用带级联删除 | 新写路径使用稳定身份和事务，不能沿用按数组下标推断来源身份 |
| 有节目表时 Liquidsoap 中段只接 `sch`，默认源没有接入该分支的兜底 | 新 UI 的「未排时段」必须有真实引擎行为对应，补齐空档兜底 |
| 当前保存节目表只落库，`start` 对已存在频道直接返回 | 需要单独的应用更新动作，不能保存后宣称已生效 |

「返回列表」。应用壳顶栏、侧栏入口与底部播放条继续保留。

- 常驻「＋ 新建」打开标准 Dialog，必填名称，可见性默认私人。
  副标题、介绍、封面为可选项，可在频道设置补充；不在创建时要求编排节目。
- 保存中阻止重复提交；失败保留输入并显示错误。取消、Esc 与关闭均不创建

- 成功后关闭对话框、插入新频道并展开其配置抽屉，提示从左侧添加系统歌单。

- 删除频道使用标准确认框，注明频道名与正在播出状态；删除不删除系统歌单。

### 4. 系统歌单直接复用

“系统歌单”指当前 HTTP 服务曲库内、侧栏已有的歌单；另一台桌面客户端独立
数据库中的歌单不在此范围。抽屉左列同时列出手动与动态歌单，提供搜索、名称、
类型、曲目数与逐行加号；右列为当前频道的歌单播放队列。

- 点左列加号，将系统歌单引用追加到右列；左列保留原项并显示「已添加」。
  同一歌单在频道内只加一项，重复添加定位到已有项；一个队列项可配置多个时段。
- 点右列项选择它并展开下方时间选择器。右列提供移除、上移/下移；拖动排序
  可作为增强，不能代替可点击、可键盘操作的移动按钮。
- 移除只修改本频道草稿，不删除系统歌单；若该项已有时段，先提示将一并移除
  这些时段，保存时以一个事务提交。取消编辑恢复原队列与时段。
- 不在推流页重做选曲、加歌或另一套歌单创建流程。这里配置的是频道节目来源
  队列，与底部播放器的个人收听队列分别运行，不能相互替换。

右列的队列顺序与时间编排约定如下，作为实施默认方案：

- 新增项默认「常规轮播」。没有指定节目的时段，按右列中常规项的顺序播放，
  每个歌单播放一轮后进入下一个，整队列循环；歌单内可选按顺序或随机。
- 设为「指定时段」后，该项只在选定周时段内参与播出，不再同时进入常规队列。
  时段内循环该歌单；到边界按节目安排切换。多段时间仍归属同一队列项。
- 指定节目优先于常规队列；重叠按显式优先级处理，右列排序不充当隐藏优先级。
- 常规队列为空但存在时间空档时，允许保存草稿，开播/应用前提示未覆盖区间
  并阻止应用；不自动拿某个指定节目或全库随机填空。全天排满时可没有常规项。
- 常规队列被指定节目接管后，回到常规队列从保留游标的下一首继续；跨时段不
  承诺续播被截断歌曲的秒位置。来源更新后按稳定曲目 ID 保留可用游标，缺失则
  从当前常规项的第一首开始。该行为需要实际引擎验证。

| 行为 | 计划语义 |
|---|---|
| 节目选择来源 | 从左列添加系统歌单 ID 到右列，不复制名称和 trackIds 形成独立可编辑歌单 |
| 空档来源 | 使用右列的常规轮播项；新配置不再另外选择单个默认歌单 |
| 系统歌单改名 | 节目引用保持 ID，读取时显示新名称 |
| 加歌、移除、排序或刷新动态规则 | 读取系统最新成员；正在播出的频道标为「待应用更新」 |
| 顺序/随机 | 每个节目可选「按歌单顺序循环 / 随机循环」；顺序模式实际保留系统排序 |
| 空歌单/全部曲目离线 | 选择器明确标记；可保存草稿，应用或开播前列出不可播来源，阻止无效应用 |
| 被频道队列引用的歌单删除 | 按系统原有删除操作执行；频道显示来源缺失，编辑时移除或换成有效来源 |
| 停播频道引用 | 读取时同样解析最新来源，缺失状态可见；系统删除操作不受频道引用限制 |
| 缺失引用（外部修改等） | 保留节目条目并显示来源缺失，允许更换，不静默切到全库随机 |

歌单成员变化与播出实例分开处理：配置始终引用系统歌单，播出引擎使用上次
成功应用的来源快照。普通改歌操作不自动重启正在播出的频道；推流页显示
更新提示，由「应用更新」读取最新内容。停播后再次开播也会读取最新内容。
播放列表变动标记由服务端处理，覆盖所有 HTTP 写入口和重新启动后的检测，
不依赖某一个浏览器 store 的回调。

### 5. 时间选择：紧凑方块周视图

周视图是时间选择器的主要交互，不再将条目列表作为主编辑器，也不使用滑块。
选择右列某个队列项后，抽屉下部显示该项的周时间选择区；切换到「指定时段」
即可选格，周视图标题始终显示正在编辑的歌单名。

- 默认布局为周一至周日七行、00–23 时二十四列，单格表示一小时。
  格子约 18–22px 见方、间隔约 2px；行列标签固定对应，整周约 540–640px
  宽、200px 高。使用可用宽度适配，在 960px 窗口的主内容区完整呈现，
  不依靠原来按列宽撑大的色块，也不设置僵硬的正方形比例导致纵向暴涨。
- 点起格再点终格可选择连续区间；按住拖动可框选同一时间范围的多日矩形。
  结束格包含在选择内，例如 08 与 09 两格表示 08:00–10:00。
  悬停和拖动期间显示日期与完整范围，释放后生成可见的时段草稿摘要。
- 支持继续添加不连续区间，已有区间点击可选中并删除、修改；框选只作用于
  当前歌单，不覆盖其他歌单。相邻同来源、同规则的区间规范化合并，反复选择
  同一区间不生成重复条目，移除时间有明确动作，不通过颜色猜测增删模式。
- 格子负责快速选范围；下方时间字段负责分钟微调，HH:MM 支持建议 5 分钟步长，
  已有任意有效分钟值均可原样保存。非整点区间用局部填充和文本摘要表示，
  不把 08:30 自动改成 08:00，也不把格子扩展为上千个分钟按钮。
- 键盘方向键移动当前格，Enter/Space 设置范围起止；日期/时间字段提供等价
  输入路径。聚焦、起点、预选和已保存区间视觉区分；名称、时间及冲突有文字
  摘要，不能只依赖颜色。小方块的命中与焦点边界要清晰，禁止透明命中区互相重叠。
- 结束时间早于开始时间表示次日结束，预览明确写「次日」。相同起止时间不
  隐式解释为全天；本轮拒绝相同值。全天轮播使用常规队列。
- 重复星期表示开始日。例如周日 22:00–02:00 覆盖周日夜间至周一凌晨。
  周视图拆成周日末尾与周一开头两段，摘要显示「周日 22:00–次日 02:00」。
  跨午夜可通过起止时间字段设置，不强迫鼠标跨越周图边缘拖动；展示、冲突
  检测和 Liquidsoap 渲染按同一规则处理。
- 新增时段与现有节目相交时给出具体日期、相交区间和歌单；默认阻止重叠，
  用户可显式选择覆盖并设置更高优先级。相同优先级重叠阻止保存，避免依赖
  数据库隐含排序。
- 其他队列项占用的时段用弱化背景与来源提示呈现，当前项用强调填充；重叠
  冲突单独标记。时间字段和摘要可精确查看所有层，不能只画最终获胜来源。
  未指定的格子表示常规队列，若无常规项则标为空档。
- 提供同一周图的「全部安排」只读概览，用于检查整体覆盖；返回当前项即可
  继续选时段，不打开第二个配置页面。本轮不做日期日历及拖拽边界缩放。
- 页面显示服务端播出时区；服务端预览和 Liquidsoap 使用同一时区，不取
  浏览器本地时间作为权威。部署时明确两容器的时区，不能默认为 Asia/Shanghai。

### 6. 配置保存与生效

穿梭框队列、排序、循环方式与周时段共用一份频道草稿，点击「保存配置」一次
提交，成功后显示「已保存，待应用」；「取消」恢复到最近保存版本。
抽屉收起、切换频道或离开页面时沿用草稿处理流程，不悄悄丢弃输入。

「应用更新」只作用于当前频道：校验引用、可播曲目、时间与冲突，生成配置，
再进入运行时更新。停播频道只保存供下次开播；播出频道应用时可能短暂重连，
操作旁明确提示这一点。未应用编辑不会停止当前输出。

状态区分「停止」「启动中」「播出中」「启动失败」及「有待应用更新」，不能
把 `active=true` 直接当成播出成功。配置校验失败保留现有输出；实际启动失败
保留已保存配置和错误状态，允许重试，不显示成功提示。运行中失败可能造成
中断，因此不承诺跨进程更新绝对无缝；通过真实 Compose 用例验证恢复行为。

### 7. 数据与代码切口（实施方案）

本地环境为用户自建测试环境。按本轮补充要求直接替换频道节目模型，不新增
迁移、旧数据兼容、旧接口兼容或系统歌单删除拦截。

1. **直接引用**：新的节目配置保存在同一数据库 settings 的
   `station.program.<stationId>`。整份 JSON 包含版本与队列，每项直接存系统
   playlistId、歌单内顺序、常规/指定模式和周时段。数组次序即歌单队列次序，
   不复制歌曲内容，不经过旧的频道内部歌单与外键绑定。
2. **原子写入**：`station_set_program` 一次事务提交整份配置；版本检查用于
   保存一致性。删除旧 `station_set_playlists/set_schedules` 命令与 DTO，
   测试环境中的旧节目配置不再承接。数据库不增加迁移链。
3. **DTO**：Rust 定义频道队列、周时段与节目配置，生成 TS；`client.ts`
   统一封装。返回歌单显示信息、可播数量、待应用状态、播出时区和错误，
   路径仅用于服务端生成 Liquidsoap 脚本。
4. **失效来源**：系统歌单允许原有删除操作；频道在下一次读取时显示来源缺失，
   不自动复制、恢复或转换。应用与开播仍校验曲目、时间和覆盖，避免无效配置
   被当成成功播出；这些是运行正确性校验，不是旧数据保护流程。
5. **取曲与渲染**：系统歌单按成员次序解析路径。常规队列使用动态请求源，
   每单取完一轮才进入下一单，随机只发生在当前歌单内；指定节目用周时段
   switch 覆盖，空档回到常规队列。保留插播优先级，前端不推进实际播放。
6. **应用通道**：`station_apply` 负责校验、重建并等待频道就绪。保存配置不
   自动停止输出；系统歌单内容变化通过来源指纹判断待更新。开停播与应用
   串行执行，启动错误返回并显示。元数据改名不自动重启推流。
7. **UI 拆分**：`BroadcastView` 提供全宽内容区；`StationPanel` 处理频道行、
   上下抽屉及频道设置；`ProgramEditor` 提供系统歌单穿梭框，
   `WeekTimePicker` 提供点选/框选与分钟编辑；新建使用标准 Dialog。
   抽屉为行内区域，不增加常驻侧栏，也不照搬从右滑入的 `SideDrawer`。
