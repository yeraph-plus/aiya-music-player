**把"记忆的文风"（何时、何故、经何过程做出决定，落在 docs/ 与 git 历史）与

分开，两者共用中性技术语域**，随后按 AGENTS.md → README → 注释分片 → 文档制度
落地，共 7 个批次。

## 2. 目标文风（本节为 AGENTS.md 对应章节的草案）

### 2.1 两个语域

| | 交付物文风 | 记忆文风 |
|---|---|---|
| 载体 | 代码注释、`///` 文档、README | docs/ 编号记录、ADR、账本 |
| 回答 | 现在是什么、为什么这样设计、证据在哪 | 何时、何故、经何过程做出决定 |
| 时态 | 现在时陈述句 | 过去时允许，日期必须真实 |
| 历史叙事 | 禁止（归 git 历史与记忆文档） | 允许且必要（"上一版是 X，因 Y 改为 Z"） |
| 第一/第二人称 | 禁止 | 第一人称允许，第二人称禁止 |
| 共同禁令 | 拟人比喻；口语词（人话、拍板、顺手、坑、翻车、挂了、搞定、抽风、收尸）；训诫式祈使（"不要回来手画""谁哪天想……会撞上"） | 同左 |

判据：注释中出现日期、轮次、人称、旧实现对比，即违反交付物语域；记忆文档中把
结论写成面向读者的禁令，即越界为训诫。

### 2.2 交付物注释三段法

按"是什么 → 为什么 → 证据"组织，三段不必齐备：

1. **是什么**：该代码/契约的行为、单位、边界、不变量（现在时）。
2. **为什么**：约束来源——性能、正确性、平台行为、既定决策。没有可靠来源就不写。
3. **证据**：测试名、docs/NN §X、ADR 编号、schema、实测数字。证据必须指向真实
   存在的目标，不造名。

规约型注释（文件头"如何扩展"段）允许中性祈使，但去除面向人的训诫与强调修辞。

### 2.3 改写对照（示意，均源自 §1 真实案例）

| 现状 | 违例 | 改写（示意） |
|---|---|---|
| `名字必须说人话——UI 横幅直接展示这条消息。` | 口语 + 命令腔 | `错误名直接展示于 UI 横幅，须为用户可读短语，不含内部标识符。` |
| `语义约定（2026-10-28 拍板）：history 表 = "保留周期内的播放记录"。` | 决策对话入注释 | `history 表仅存保留周期内的播放记录（语义定义：docs/NN §X）。` |
| `谁哪天想"顺手在这儿建一张"，会先撞上它。` | 拟人威慑 | `该占位使 beets-store 侧建表在名字检查处显式失败，避免两侧各自建同名表。` |
| `**要用新图标就加一行**，不要回来手画 path。` | 训诫 | `新图标在表中注册一行，不手写 path。` |
| `暂停时直接跳 0 会"啪"一下没掉，像渲染挂了` | 拟声 + 比喻 | `暂停时若直接置 0，振幅瞬间消失，观感等同于渲染中断。` |
| `会让列表每 30 s 重拉一次，看起来像在抽风。` | 拟人 | `会使列表每 30 秒整体重载，出现可见闪烁。` |

改写纪律：只换语域，不删事实。被剥离的日期/轮次/旧实现叙事若有保留价值，落到
对应 docs/NN 或 ADR，注释保留指针；无保留价值则删除（git 历史可查）。

### 2.4 不算违例的情形

- 技术复合词：镜像、像素、识别、区别、别名。
- 规约段的中性要求句（"必须先编译 sidecar"）。
- 字符串字面量中的 UI 文案。
- 对 docs 标题的引用（即便被引标题含口语词）。

## 3. 文档制度（本节为 AGENTS.md 对应章节的草案）

### 3.1 docs/ 四型制

| 类型 | 职责 | 生命周期 |
|---|---|---|
| 调研 | 问题、选项、证据、结论 | 完成即 closed，结论由 AGENTS.md 约束/后续文档承接 |
| 计划 | 批次拆分、验收判据 | 批次收尾标 closed，剩余项转入账本 |
| 审计 | 体检、问题清单 | 发现项转入计划或账本后 closed |
| 账本 | "还剩什么"的唯一真源（现 docs/35） | 持续更新，不 closed |

架构级决策不再单设 ADR：决策事实并入 AGENTS.md §3 约束，决策过程与证据留在
编号文档（见 §3.3）。

每份编号文档头部固定 3 行元信息：`类型 / 状态 / 关联`（supersedes、superseded-by、
相关编号）。

### 3.2 编号与命名

- 命名 `NN-slug-YYYY-MM-DD.md`，日期为写作日；新文档编号取现存最大值 +1（下一份 59）。
- 历史撞号（10、42）不改编号——交叉引用以编号为键，重排只是让歧义转移；由索引
  文件显式登记两处撞号的完整文件名映射。
- 00–09 补日期后缀属文件重命名，执行前须全仓 grep 旧文件名确认零引用。
- 标题体例统一为 `# NN · 标题（YYYY-MM-DD）`。
- 会话级临时物（工作区根的 `.commitmsg-*.txt` 等）不进 docs/；会话结论要保留就
  落成编号文档，否则不落盘。

### 3.3 架构决策的登记（2026-11-01 修订：废弃 ADR 结构）

ADR 体系停止使用，docs/adr/ 六份记录删除，其中仍然成立的事实并入根 AGENTS.md
§3 约束（每条标注原 ADR 编号与 docs 来源）。代码注释中现存约 20 处 ADR-000N
指针，由 G5/G6 改写为指向 AGENTS.md §3 对应条目（AGENTS.md 提供映射表）。
此后架构决策的登记流程：

1. 决策过程与证据（背景、备选方案、实测）落在所在批次的编号文档；
2. 决策事实（现行约束）同批更新 AGENTS.md §3，注明来源编号；
3. 推翻既有约束时直接修改 AGENTS.md §3 对应条目，并在新编号文档记录来由。

需要登记的情形沿用四条判据：跨进程/跨仓边界的契约决定；难以回退的决定
（数据格式、分发形态、签名与信任）；推翻既有约束；约束后续多个批次的架构选择。

## 5. 风险与边界

- **交叉引用承重**：不重排历史编号；重命名文件前先全仓 grep 旧名。
- **doctest**：`///`/`//!` 改动可能影响文档测试，G5/G6 以全量 cargo test 验收。
- **截图**：G2 以 `npm run dev:ui`（mock 后端）加浏览器自动化截图，存 `docs/img/`
  提交入仓；README 标注截图为演示数据。
- **自动门禁词表要窄**：`check:style` 只收高精度词（人话、拍板、顺手、翻车、搞定、
  抽风、收尸）与注释行日期戳模式 `\d{4}-\d{2}-\d{2}`，附白名单文件；宽泛词
  （像、别、坑、必须）误报率高，只进人工批改，不进自动门禁。
- **不做**：不重写全部注释（只治理违例）；不动逻辑；不引入英文注释；不给历史
