# 打包（P5 第一刀）：安装包构建与安装/卸载验证

> 日期：2026-10-24　范围：让 `tauri build` 真正产出可装的安装包，并做安装→运行→卸载的闭环验证。
> 不在本轮：签名（Authenticode）、4h soak、自动更新、安装包体积优化、CSP/权限收窄（见 §7）。

## 1. 之前为什么打不出包

`src-tauri/tauri.conf.json` 里 `bundle.active = false`，且没有任何地方把
`aiya-audio-host.exe` 放进安装目录。就算把 `active` 打开，装出来的应用也会
在 `setup()` 阶段报"找不到 sidecar"直接退出 —— 因为宿主是按
`current_exe()` 同目录找它的：

```rust
// src-tauri/src/sidecar.rs
let sibling = exe.parent().unwrap().join("aiya-audio-host.exe");
```

所以打包要解决的是三件事，不只是"打开一个开关"。

## 2. 三处改动

### 2.1 sidecar 进包：`externalBin` + 构建前置脚本

Tauri 的 `externalBin` 要求文件按**目标三元组**命名
（`aiya-audio-host-x86_64-pc-windows-msvc.exe`），打包时它会剥掉后缀复制到
安装目录，正好落成宿主找的 `aiya-audio-host.exe`。

新增 `tools/build-sidecar.mjs`：读 `rustc -vV` 的 `host:` 得到三元组 →
`cargo build -p aiya-audio-host --release` → 拷到 `src-tauri/binaries/`。
接在 `beforeBuildCommand`：

```
npm --prefix ui run build && node tools/build-sidecar.mjs
```

为什么必须显式编：sidecar 不是 `aiya.exe` 的 Cargo 依赖，`tauri build` 不会
顺带编它；profile 也必须跟主程序一致，否则包里混进一个 debug 引擎（体积 ×10、
性能不对）。产物 `src-tauri/binaries/` 已加进 `.gitignore`。

### 2.2 启用打包：NSIS + currentUser + 双语言

```json
"targets": ["nsis"],
"windows": { "nsis": { "installMode": "currentUser", "languages": ["SimpChinese", "English"] } }
```

只出 NSIS：MSI 需要 WiX 且对 per-user 安装支持差，v1 没必要两条路都铺。
`currentUser` 免 UAC，本地播放器不需要机器级安装。

### 2.3 许可文件进包

GPL-3.0 分发要求"许可全文 + 第三方 notices + 源码获取方式"随二进制走。
资源用 map 形式落进 `licenses/`（源文件在仓库根/`licenses/`，不复制一份到
`src-tauri/` 里）：

| 文件 | 内容 |
|---|---|
| `licenses/LICENSE` | GPL-3.0 全文（gnu.org 原文，674 行） |
| `licenses/THIRD-PARTY-NOTICES.md` | 实际分发组件清单 + MPL-2.0（Symphonia）说明 + 外部依赖（Python/beets 不随包） |
| `licenses/CARGO-DEPS.md` | **525 个 registry crate** 的名称/版本/许可/仓库，`tools/gen-notices.mjs` 生成 |
| `licenses/SOURCE-OFFER.txt` | GPL-3.0 §6(d) 源码获取要约 |

顺手纠正了一处会误导合规的东西：早期计划写"notices 含 mpv/FFmpeg"，
而 v1 是原生引擎（ADR-0006），**包里没有 mpv/FFmpeg**。notices 只声明
真的在包里的组件，别照抄旧计划。

## 3. 构建结果

```
node ui/node_modules/@tauri-apps/cli/tauri.js build     # 从仓库根跑
```

| 阶段 | 耗时/结果 |
|---|---|
| `vite build`（ui） | 1.18s，262 modules，JS 295.58 kB（gzip 98.61 kB） |
| `cargo build --release`（含 LTO + strip） | 6m35s |
| NSIS 打包 | 下载 nsis-3.13 与 nsis_tauri_utils 0.5.3（首次），`makensis` 出包 |

产物：

| 文件 | 大小 |
|---|---|
| `target/release/aiya.exe` | 13,895,680 B / **13.25 MiB** |
| `target/release/aiya-audio-host.exe` | 2,135,552 B / **2.04 MiB** |
| `target/release/bundle/nsis/AIYA Music_0.1.0_x64-setup.exe` | 4,258,996 B / **4.06 MiB** |

安装包 4 MiB 而不是 17 MiB，是因为 NSIS 用 LZMA 压了主体；解开后安装目录
约 16 MB（另加 WebView2 走系统运行时，不占包体）。

## 4. 闭环验证（真机，不是"应该可以"）

### 4.1 直接跑 release 产物

| 检查 | 结果 |
|---|---|
| 主进程存活 | PID 34212 在 8s / 16s 两次采样均存活，内存 37,680 K 不涨 |
| sidecar 起来 | `aiya-audio-host.exe` 独立 PID 同时在线（握手成功才会常驻） |
| DB 建库 | `%APPDATA%\dev.aiya.music\library.sqlite`（+`-wal`/`-shm`）时间戳更新 |
| beets 脚本落盘 | `%APPDATA%\dev.aiya.music\sidecar\beets_sidecar.py` 被 `ensure_script` 写出 |
| 强杀主进程后的孤儿回收 | `taskkill /F` 后 10s 内 `aiya-audio-host.exe` 自行退场（8s 孤儿窗口） |

### 4.2 安装 → 运行 → 卸载

```
"AIYA Music_0.1.0_x64-setup.exe" /S      # 静默安装
"%LOCALAPPDATA%\AIYA Music\aiya.exe"     # 运行（12s 冒烟）
"%LOCALAPPDATA%\AIYA Music\uninstall.exe" /S
```

| 检查 | 结果 |
|---|---|
| 安装落点 | `%LOCALAPPDATA%\AIYA Music`（静默模式下 `/D=` 被忽略，走 currentUser 默认路径） |
| 目录内容 | `aiya.exe`、`aiya-audio-host.exe`、`licenses/`（4 个文件齐全）、`uninstall.exe` |
| 安装版运行 | `aiya.exe` + `aiya-audio-host.exe` 同时在线，说明安装目录里 sidecar 定位正确 |
| 卸载 | 退出码 0，安装目录被完全删除（`ls` 返回 No such file） |

> `/D=` 被忽略这点值得记住：想装到指定目录做自动化测试，只能改
> `installMode`/模板或用 `TEMP` 覆盖，别指望 `/D`。

## 8. 一个操作注意

`beforeBuildCommand` 的 cwd 是**调用 tauri CLI 时的工作目录**（不是
`src-tauri/`），所以 `node tools/build-sidecar.mjs` 这种相对路径只在仓库根
执行时成立 —— 别在 `ui/` 里跑 `tauri build`。
